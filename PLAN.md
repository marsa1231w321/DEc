# DEc — обязательный план выполнения

Этот документ — обязательный roadmap проекта, предоставленный владельцем проекта и дополненный текущими статусами. Читать целиком до начала работы. Порядок фаз задаёт порядок исполнения; внутри фазы параллелить только независимые задачи. Фаза не закрыта, пока DoD всех задач не выполнены и CI не зелёный. GitHub Actions run 41374289046 для `main` успешен; Фаза 0 остаётся открытой до F0.2, F0.6–F0.8.

**Срез статусов:** 2026-11-02. Статусы отражают рабочую копию на дату записи, а не утверждение о полном соответствии DoD. Ранее сделанные прототипные функции отмечены как `PARTIAL`, пока не выполнен весь контракт задачи.

## Обязательные соглашения

- **BREAKING** — меняет совместимость формата `.DE` или публичного API. Требует миграции и миграционного теста; без них задача не закрывается.
- **Bug-class** — дефект существующего поведения, заведённый в трекере, не фича roadmap.
- **Pre** — предусловия. Не начинать задачу до закрытия всех её Pre.
- **DoD** — проверяемое определение завершения. Если критерий нельзя проверить, уточнить его до начала реализации.
- **Risk** — вероятные поломки или архитектурные риски; перед изменением перечитать.
- Сроки и оценки намеренно не задаются. Приоритет — корректность, зависимости и проверяемый результат.

## Законы проекта

1. Ни одна задача не начинается без выполненных Pre.
2. Ни одна задача не закрывается без DoD и зелёного CI.
3. Любое BREAKING-изменение проходит через F0.4 (версии и миграции).
4. Тесты, CI и headless — Фаза 0, не откладываются на будущие фазы.
5. Не дублировать задачи; повторяющиеся пункты объединять или явно разграничивать.
6. Bug-class не выдавать за roadmap-фичу.
7. Физическое ядро — по отдельной AAA-физической директиве. Этот план охватывает редакторские обвязки (S4), а не заменяет директиву.

## Статусы

- `NEXT` — следующая незаблокированная работа по последовательности.
- `TODO` — не выполнено, может начаться после предшествующих пунктов плана/фазы.
- `BLOCKED` — есть незакрытые Pre или внешний блокер.
- `PARTIAL` — в прототипе есть часть поведения, но DoD задачи не достигнут.
- `DONE` — DoD выполнен и подтверждён тестами и CI.

### F0.1 — Scene Graph

- **Статус:** `DONE`; контракты графа и сохранения покрыты headless-тестами, CI run 41374289046 завершился успешно.
- **Pre:** нет.
- **Задача:** узлы сцены, local/world transforms, parent/child, группы, теги, слои и стабильные ID.
- **DoD:** API `add/remove/reparent/query`; сериализация; тесты на запрет циклов в иерархии, пересчёт world-transform и сохранение ID при save/load.
- **Risk:** смена модели сцены влияет на все инструменты; сделать до полного undo, автосейва и валидации.
- **Контекст текущей реализации:** `Scene.graph` — источник истины; объекты и свет доступны как read-only tuple-представления. Карта версии 6 получила необязательное `scene_graph` расширение; старые карты загружаются плоско. API, transform, цикл, удаление и save/load покрыты headless-тестами; workflow успешно прошёл на commit `c9fb9dad0a7613bcbf6d4636ebb516419944dc71`.

### F0.2 — Командная модель

- **Статус:** `PARTIAL`; DoD реализован и локально проверен, ожидается CI для этой ревизии перед закрытием статуса.
- **Pre:** F0.1, F0.3, F0.4 (для сериализуемого журнала команд).
- **Задача:** `Command` API с `do/undo`, единый стек и транзакции (несколько команд — один undo-шаг); автосейв поддерживает сериализацию/восстановление команд, если это нужно выбранной модели.
- **DoD:** команды покрывают преобразования, свойства, добавление/удаление и логику; тест «undo после save/load».
- **Risk:** если построить команды до event bus, команды придётся переписывать.
- **Контекст:** `dec_engine/commands.py` содержит property/add/remove/transaction commands и единый `CommandStack`. UI-адаптер хранит diff-команды вместо полных scene snapshots; `.DE` сохраняет undo/redo records в additive `command_history`, что покрыто undo-after-save/load-тестами. Capture для legacy UI-обработчиков временно строит before/after сериализованные состояния для расчёта минимального patch; сами снимки не хранятся в истории. Headless-тесты и локальные Ruff/Pyright/smoke-проверки проходят; удалённый CI ещё не запускался на этой ревизии.

### F0.3 — Событийная шина

- **Статус:** `DONE`; autosave dirty/revision и validation подключены как event consumers, headless-интеграция проверена.
- **Pre:** нет.
- **Задача:** типизированные observer-события изменений сцены, ресурсов и выделения. Undo, автосейв, валидация, диагностика и профилировщик подписываются на события, не опрашивая состояние.
- **DoD:** типы событий определены; порядок доставки детерминирован и проверен тестом; подписчики освобождаются без утечек.
- **Risk:** порядок доставки влияет на детерминизм и воспроизводимость.
- **Контекст:** `dec_engine/events.py` содержит `SceneChanged`, `ResourceChanged`, `SelectionChanged`, упорядоченный `EventBus` и явную отписку через `Subscription.close()`. `SceneEventConsumers` подписывает dirty/revision, recovery autosave и актуальную валидацию на события сцены/ресурсов. Редактор читает кэш валидации при запуске playtest и сохранении; listener закрывается при замене сцены и закрытии редактора. Headless-регрессии проверяют dirty state, ресурсную повторную проверку и unsubscribe.

### F0.4 — Версионирование `.DE` и миграции

- **Статус:** `DONE`; все доступные legacy golden maps v1–v5 проверены, миграционные и malformed-manifest тесты проходят. Обязателен до P1.3 и любого BREAKING-изменения.
- **Pre:** в плане не задано; перед проектированием изучить все существующие схемы карт и пакетов и согласовать границы формата.
- **Задача:** `format_version` в manifest; отдельный слой `migrate(old) -> current`; тест миграции для каждого перехода; golden-файлы старых версий в репозитории.
- **DoD:** файл версии N-2 открывается и мигрирует тестом; повреждённый или неподдерживаемый файл даёт понятную ошибку, а не необработанный crash.
- **Risk:** изменение формата без миграции уничтожает доступ к пользовательским картам.
- **Контекст:** `CURRENT_PROJECT_FORMAT_VERSION = 6`; новые карты записывают `format_version: 6` и совместимый `version: 6`. `migrate_project_manifest(old)` копирует manifest и последовательно выполняет переходы; 3→4 переносит legacy-поля глобального освещения в направленный свет, после чего `load_project()` читает нормализованный список. Golden-карты версий 1–5 и headless-тесты лежат в `tests/fixtures/projects/` и `tests/test_project_migrations.py`; проверены загрузка сцен/света, ключи версии и ошибки при отсутствующей scene.json/невалидном lighting. Fixtures синтезированы из текущего валидного payload по подтверждённым версиям загрузчика, а не являются архивными пользовательскими файлами. Локальные `ф.DE` и `фы.DE` распознаны и проверены как корректные `DEcAssetPack` v1, а не карты. Формат asset pack не мигрируется этим слоем.

## Bug-class — Windows 10 Snap resize завершает процесс

- **Статус:** `MITIGATED / PENDING MANUAL VERIFICATION`; это дефект, не roadmap-функция.
- **Факт:** предоставленный traceback Python 3.15.0 / pyGLFW 2.11.0 завершился fatal error `PyEval_RestoreThread` внутри `glfw.poll_events()` с `current Python thread state is NULL`.
- **Изменение:** Python-callback’и GLFW заменены опросом состояния мыши/курсора/фокуса в основном цикле; Tk resize объединён таймером 16 мс, нулевые/единичные размеры и повторный размер пропускаются.
- **Проверка:** headless-тесты и отдельные GLFW resize/poll smoke-проверки проходят. Автоматический smoke не моделирует связку embedded GLFW + Tk или drag-to-snap.
- **Остаток:** подтвердить вручную на Windows 10: перетащить окно к верхнему краю, дождаться Snap/maximize, восстановить/изменить размер, проверить продолжение рендера и ввод. До этого не отмечать баг исправленным окончательно.

## Фаза 2 — Сцена

### P2.2 — Гизмо и преобразования

- **Статус:** `PARTIAL`; headless-математика гизмо, snapping, pivots, измерения и генерация геометрии готовы и покрыты тестами, но 2D/3D-визуализация и drag-взаимодействие требуют ручной GUI-проверки.
- **Pre:** F0.1 (закрыт).
- **Задача:** translate/rotate/scale gizmo в 3D и 2D; локальные/глобальные оси; ввод чисел; snapping по шагу, углу, размеру; pivots center/individual/cursor; симметрия, измерения, snapping к вершинам.
- **DoD:** гизмо в 2D и 3D; настраиваемый snapping; точный ввод.
- **Risk:** локальные/глобальные оси зависят от модели иерархии, поэтому должны учитываться в F0.1.
- **Контекст:** `dec_engine/gizmo.py` содержит `GizmoSettings` (mode/space/pivot + шаги snapping), `axis_vectors()` (global/local), `translate_position()`, `rotate_rotation()` (axis-angle поверх Euler XYZ), `scale_axes()`, `pivot_point()` (center/individual/cursor), `measurement()`, `snap_to_vertices()` и `gizmo_line_segments()` для 3D-геометрии без GL. `editor.py` хранит `self.gizmo_settings` и использует общий `snap_value()` вместо дублированной математики в 2D-сетке. Pyright include расширен на `dec_engine/gizmo.py`. Покрыто `tests/test_gizmo.py`. Остаток: отрисовка гизмо в `renderer.py`, drag/hit-testing в 2D и 3D, симметрия — требуют ручной GUI-проверки; «точный ввод» уже обеспечен существующими полями объекта.

## Сквозные требования

### S1 — Безопасность

- Рассматривать zip-slip при распаковке `.DE` и ZIP-импорте.
- Проверять path traversal в MTL и внешних ссылках моделей.
- `ffplay` — внешний процесс: таймауты, отсутствие shell-инъекций, оценка sandbox; запланировать решение о `miniaudio`/`sounddevice`.
- Определить модель безопасности плагинов до P6.3.
- **DoD:** тесты zip-slip и path traversal выполняются в CI.
- **Risk:** недоверенные ассеты могут вызвать запись/чтение нецелевых файлов; не ослаблять текущие проверки.

### S2 — Доступность

- Клавиатурная навигация, контраст, масштабирование шрифтов.
- **DoD:** базовый аудит до Фазы 6.
- **Risk:** поздний аудит приведёт к переделке UI.

### S3 — Производительность save/load

- Ленивое чтение тяжёлых ресурсов, кэш распаковки, фоновая распаковка.
- **DoD:** время открытия крупной карты укладывается в измеримый порог P5.1.
- **Risk:** «не блокирует» без числа и целевой машины невозможно проверить.

### S4 — Согласование с AAA-физической директивой

- Solver, CCD, islands/sleeping, ragdoll, cloth, destruction, determinism, fixed timestep и debug physics определяются отдельной директивой.
- Этот roadmap задаёт только редакторские обвязки: авторинг коллайдеров/триггеров/слоёв/параметров и визуализацию.
- **DoD:** P3.1 основан на зафиксированном физическом фундаменте (fixed timestep, слои, broadphase/narrowphase/solver).
- **Risk:** при конфликте двух документов остановиться и согласовать их до кода. AAA-директива не обнаружена в доступных файлах при составлении README.

### S5 — Win32-only риск

- Абстракция host-window выполняется в F0.7; полноценная кроссплатформенность — отдельная задача.
- **DoD:** F0.7 закрыта.
- **Risk:** не добавлять новые Win32-зависимости без отражения в F0.7.

## Будущий набор приложений DEc

Разделять приложения только после стабилизации scene graph, модели ресурсов и публичных API:

1. Выделить ядро DEc: сцена, сериализация/миграции, ресурсы, импорт, рендер и plugin contracts.
2. Закрепить автоматические проверки совместимости и набор тестовых проектов.
3. Определить межпроцессный формат сообщений и общий механизм открытия проектов без дублирования данных.
4. Постепенно выносить инструменты карт, анимации, ресурсов и runtime/build.
5. Пока отдельные программы не достигли полноты, сохранять единый режим работы с тем же проектом.

Рабочие названия: **DEc Hub**, **DEc Map**, **DEc Motion**, **DEc Assets**, **DEc Runtime**. Сегодня это только перспективная структура и шаблоны/вкладки единого приложения, не существующие самостоятельные продукты.

- **DoD:** каждый вынесенный инструмент проходит те же тесты, что встроенный, и открывает тот же проект.
- **Risk:** ранний вынос до стабильного API приведёт к двойной поддержке и несовместимым форматам.

## Правила для AI-агента и команды

1. Перед задачей прочитать её Pre/DoD/Risk; если Pre не закрыты — не начинать, зафиксировать блокировку.
2. До кода сделать DoD проверяемым.
3. Любое отклонение (новая зависимость, иной подход, BREAKING) сначала отразить здесь, потом реализовывать.
4. Bug-class — в трекер, не маскировать его под roadmap-фичу.
