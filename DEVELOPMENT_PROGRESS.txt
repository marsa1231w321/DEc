Краткое состояние разработки
----------------------------
- DEc остаётся единым прототипом на Python/Tkinter/GLFW/ModernGL.
- Карта `.DE` записывается с `format_version: 6` и совместимым `version: 6`; миграционная оболочка принимает версии 1–6, есть synthetic golden-архивы 1–5, переход 3→4 переносит legacy global lighting в список источников.
- Актуально: `Scene.graph` хранит сущности и иерархию; `Scene.objects`/`Scene.lights` — неизменяемые tuple-представления. F0.1 и F0.5 закрыты после успешного GitHub Actions run 41374289046.
- Есть первые реализации undo/redo на снимках всей сцены, recovery-файла и проверки сцены. Они PARTIAL по обязательному плану, не закрывают соответствующие DoD.
- Добавлены конфигурация CI, pytest, Ruff и Pyright, а также headless-регрессии. Удалённый Actions run успешен; branch protection остаётся настройкой GitHub-репозитория вне этих локальных коммитов.
- F0.3 и F0.4 выполняются независимо от CI; F0.2 начнётся после выполнения их собственных критериев. P1.3 остаётся зависимой от полного F0.4.

Ранее выполненные прототипные улучшения
---------------------------------------

1. История действий — PARTIAL (план F0.2/P2.1).
   - Кнопки отмены/повтора, Ctrl+Z/Ctrl+Y.
   - Для ряда действий сохраняется снимок полного состояния сцены; жест перетаскивания в 2D-сетке записывается одним действием.
   - Ограничения: максимум 30 действий и 128 МиБ; история только в памяти; отсутствуют Command API, транзакции для всех инструментов и undo после save/load.
   - Реализация: `dec_engine/editor.py`.

2. Recovery/autosave — PARTIAL (план P1.2).
   - Каждые 30 секунд изменённая сцена записывается в отдельный recovery-файл; тест и playback приостанавливают сохранение.
   - При запуске можно восстановить копию, удалить её или отложить решение. Обычный файл карты автоматически не перезаписывается.
   - Ограничения: только один файл, фиксированный интервал, нет retention-настроек и полноценного dirty-state UI; полное закрытие P1.2 по плану зависит от F0.2/F0.4.
   - Реализация: `dec_engine/editor.py`, формат сохраняется через `dec_engine/project.py`.

3. Валидация сцены — PARTIAL (план P1.1).
   - Проверяются основные поля геометрии, индексы, размеры/цвета, назначенные файлы, свет, параметры карты теней и ссылки логики.
   - Игровой тест блокируется при найденных проблемах; при сохранении черновика можно подтвердить продолжение.
   - Ограничения: нет уровней blocker/warning, навигации к объекту/свойству, полной проверки animation/MTL references.
   - Реализация: `dec_engine/validation.py`, `dec_engine/editor.py`.

4. Платформенные и редакторские исправления из предыдущих сессий.
   - Управление камерой/тестом, проверка захвата мыши, дополнительный вывод, отделяемые панели, маркер направления света и инструменты анимации.
   - Подробный перечень актуального поведения и ограничений см. в README.md. Не считать непроверенные детали закрытыми задачами roadmap.

Windows 10 Snap resize — регрессия обрабатывается
------------------------------------------------
- Пользователь предоставил фактический fatal traceback: Python 3.15.0 / pyGLFW 2.11.0 завершился в `glfw.poll_events()` с `PyEval_RestoreThread` и `current Python thread state is NULL`.
- В `dec_engine/app.py` удалены три Python-callback’а GLFW (фокус, мышь и положение курсора); те же данные теперь опрашиваются из основного цикла через `ViewportInputState`. Опрос не выполняется, когда приложение не в фокусе. Это устраняет пользовательские ctypes callback-переходы из event pump в Python, сохраняя ввод камеры и теста.
- В `dec_engine/editor.py` resize события объединяются таймером Tk 16 мс; временные размеры 0/1 игнорируются, одинаковые размеры не отправляются повторно, отложенный callback отменяется при закрытии редактора. Размер framebuffer теперь читается после обработки GLFW-событий; при свёрнутом/нулевом framebuffer цикл ждёт события вместо активного вращения.
- Добавлены `tests/test_window_input.py`: пять тестов покрывают состояние кнопок, относительное движение, сброс baseline, polling GLFW и объединение resize-событий. В Python 3.15.0 прошли standalone GLFW resize/poll probes с callback и без него, а также Tk + embedded GLFW probe с 24 последовательными изменениями размера; эти автоматические probes не воспроизводят настоящий drag-to-snap Windows 10.
- Финальные локальные проверки после изменения: pytest — 18 passed; unittest discovery — 18 passed; Ruff lint — passed; Ruff format check — 3 files already formatted; Pyright — 0 errors/warnings/informations; compileall — exit 0; `smoke_test.py` — exit 0 (`0.1.0 5`). Удалённый Actions run недоступен без Git remote.
- Проверка точного сценария Windows 10 привязки окна к верхнему краю остаётся `PENDING`: в доступной среде невозможно имитировать пользовательский drag/snap. Исправление следует считать mitigation до ручной проверки этого сценария.
